# CLAUDE.md — JINA: первые накопления для 18–24 (портфолио-кейс)

Хакатон BCC Future Talent закончился. Теперь это портфолио-кейс продакт-менеджера для LinkedIn:
сайт-кейс + живой мобильный прототип, деплой на Vercel. Главное — сильный UX/UI и честность:
никаких обещаний доходности и выдуманных данных.

**Источник правды для v3 — `docs/08-jina-v3.md`** (аудитория только 18–24, название JINA, уроки, дизайн-направление).
Он главнее стратегии там, где они расходятся; числа и расчёты — по-прежнему из стратегии §7.

## Начало каждой сессии (обязательно, по порядку)

1. Прочитай `docs/PROGRESS.md`: что сделано, что в работе, что следующее. Продолжай с «Следующий шаг».
2. Прочитай `docs/BUILD-SPEC.md`. Это ТЗ на прототип: экраны, расчёты, тесты, критерии приёмки.
3. Остальные документы читай только нужным разделом (см. «Экономия токенов»).

Работа может переходить между аккаунтами Claude посреди задачи.
Поэтому `docs/PROGRESS.md` и git — единственная память проекта. Держи их актуальными.

## Жёсткие правила (нарушение = проигрыш на защите)

- **Не выдумывай данные пользователей.** Никаких тепловых карт, «опросили N человек», процентов
  конверсии, отзывов. Экран «Метрики демо» показывает только события текущей демо-сессии с пометкой
  «демо-сессия, не исследование».
- **Не обещай доходность.** Запрещены обещания: «доход», «заработок», «гарантия» (как обещание),
  «депозит», «как вклад», «Без комиссии», «копи», «выгодно», «вырастет». Корректные отрицания
  разрешены и нужны: «доходность не гарантируется», «не является вкладом».
  Проверяй смысл фразы, а не только слова.
- **Не заявляй уникальность:** без «первое цифровое золото в Казахстане», «у бирж этого нет».
  Без исторических цифр вроде «−28%» без источника.
- **Курс покупки и продажи — всегда рядом**, где есть цена. Золото на главной оценивается по цене продажи.
- **Блок риска** — на экране суммы, подтверждения и успеха покупки.
- **Партнёры вымышленные** и подписаны «(демо)». Их балансы — «только просмотр», с временем обновления
  и словом «ориентировочно». Это не «доступно для трат».
- **Лимиты** подписаны как условные продуктовые («условный лимит демо»), не как нормы AML/KYC.
- **Все данные синтетические.** В углу или в профиле — пометка «Синтетические данные для демо».

## Порядок работы

1. Сначала данные и расчёты с тестами, потом экраны. Не жди Figma: стиль в переменных, подставим позже.
2. Строго по приоритетам из ТЗ: P0 → P1 → P2. Не начинай P1, пока P0 не проходит приёмку.
3. После каждой завершённой задачи:
   - `npm run build` и `npm test` зелёные;
   - если есть Playwright или браузер — скриншот 390×844 и посмотри на него сам;
   - обнови `docs/PROGRESS.md` (Сделано / Следующий шаг / Расхождения / Известные проблемы);
   - `git commit` с понятным сообщением.
4. Не рапортуй «готово», не проверив работу.

## Экономия токенов (лимит аккаунта ограничен)

- Не перечитывай большие документы целиком. В стратегии нужен раздел 7, в ревью —
  «Числа и отображение» и «Противоречия». Ищи по заголовку (`grep -n "^## "`), читай диапазон строк.
- Правь файлы точечно. Не переписывай файл целиком ради пары строк.
- Не запускай dev-сервер в цикле с длинным выводом. Для проверки — `npm run build`, тесты, скриншот.
- Не делегируй работу субагентам без явной необходимости: каждый стартует с нуля и тратит токены.
- Коротко в чате: что сделал, что дальше. Подробности — в `docs/PROGRESS.md` и коммитах.
